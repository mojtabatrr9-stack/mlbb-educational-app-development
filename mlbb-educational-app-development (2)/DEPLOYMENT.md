# Nexus — نصب، استقرار و محدودهٔ تحویل

> نسخهٔ انگلیسی کوتاه: [`DEPLOYMENT.en.md`](DEPLOYMENT.en.md)

## ۰. اجرا بدون نصب محلی (برای کامپیوترهای قدیمی، مثل ویندوز ۷)

- **GitHub Codespaces (پیشنهادی):** پروژه را در GitHub قرار دهید → Code → Codespaces → Create. کانتینر توسعه (`.devcontainer/`) خودش PostgreSQL را راه می‌اندازد، وابستگی‌ها را نصب می‌کند، اسکیمای دیتابیس را اعمال و دادهٔ اولیه را وارد می‌کند. سپس `npm run dev` را بزنید و پورت ۳۰۰۰ را باز کنید. فقط یک مرورگر لازم است.
- **Docker:** با `docker compose up -d` اپ و PostgreSQL هم‌زمان بالا می‌آیند.
- **استقرار ابری:** Supabase (دیتابیس) و Vercel یا Render (اپ). جزئیات در `DEPLOYMENT.en.md`، بخش ۲. برای Render، `Dockerfile` آماده است.
- **CI:** `.github/workflows/ci.yml` روی هر push این مراحل را اجرا می‌کند: بررسی فرمت، TypeScript، lint، تست واحد، ساخت دیتابیس و seed، build، تست e2e (axe، خطای 404، موبایل و RTL، آفلاین) و تست ادمین.
- **فایل‌های باینری:** آیکون‌ها، favicon، آیکون maskable و Apple و تصویر OG در هر build از روی `public/icon.svg` ساخته می‌شوند (`npm run assets`). پرترهٔ هیروهای غایب دوباره دانلود می‌شود. اگر تصویری همچنان در دسترس نباشد، جایگزین رنگی ساخته‌شده نمایش داده می‌شود و هرگز تصویر شکسته دیده نمی‌شود. فونت‌ها از پکیج‌های `@fontsource-variable` می‌آیند و Next.js آن‌ها را به‌صورت WOFF2 کنار برنامه منتشر می‌کند.
- **دادهٔ اولیه:** `npm run db:seed` تکرارپذیر است و ویرایش‌های مالک را بازنویسی نمی‌کند.

## ۰٫۱. زبان‌ها و فهرست کامل هیروها (فاز ۲ و ۳)

- مسیرها زبان‌دار هستند: `/en` و `/fa`. ریشهٔ سایت بر اساس کوکی یا زبان مرورگر هدایت می‌شود. صفحهٔ فارسی از سمت سرور با `dir="rtl"` و فونت وزیرمتن رندر می‌شود؛ اعداد فارسی و تاریخ شمسی خودکارند.
- همهٔ متن‌های رابط در `messages/en.json` و `messages/fa.json` هستند و تست واحد برابری کلیدها را بررسی می‌کند. فیلدهای محتوا به شکل `{ en, fa }` ذخیره می‌شوند؛ پنل ادمین هر دو زبان را کنار هم نشان می‌دهد، فیلدهای بدون ترجمه را علامت می‌زند و با دکمهٔ «پیش‌نویس ترجمهٔ فارسی» از هوش مصنوعی (فقط مالک) پیش‌نویس می‌گیرد.
- `node scripts/import-roster.mjs` فهرست کامل هیروها (۱۲۴ هیرو)، آیکون مهارت‌ها، پرتره‌ها و آیتم‌ها را از منابع پیکربندی‌شده (`ASSET_SOURCES`) دانلود و محلی می‌کند. گزارش در `ICON_REPORT.md`. سپس `npm run db:seed` آن‌ها را وارد دیتابیس می‌کند و رکوردهای قدیمی را بدون دست زدن به ویرایش‌های مالک دوزبانه می‌کند.
- **صداقت داده:** مهارت‌های واردشده انگلیسی‌اند و در نمای فارسی با پیام «ترجمه در انتظار» نمایش داده می‌شوند؛ کول‌داون/هزینه با «—» و آمار پایه با برچسب «تخمینی» مشخص می‌شوند. منبع فعلی تا هیروی Chip را پوشش می‌دهد؛ هیروهای جدیدتر را از پنل اضافه کنید. راهنمای ترجمه: `CONTENT_GUIDE.md`.

## ۱. چه چیزی ساخته شده است؟

نسخهٔ اجرایی این پروژه **Next.js App Router + React + PostgreSQL + Drizzle** است. دو بخش دارد:

- `/`: اپ عمومی واکنش‌گرا و نصب‌پذیر (PWA).
- `/admin`: پنل مالک؛ بدون ورود تنها پیش‌نمایش داده‌های عمومی نمایش داده می‌شود.

همچنین:

- `mobile/`: سورس **پوستهٔ Flutter** برای Android و iOS؛ تمام امکانات آنلاین از اپ وب بارگذاری می‌شوند و یک کتابخانهٔ بومیِ فقط‌خواندنی برای هیروهای دانلودشده وجود دارد. این یک بازنویسی کامل رابط وب با ویجت‌های بومی Flutter نیست.
- `database/schema.sql`: خروجی SQL ساختار Drizzle.
- `database/supabase-access.sql`: سیاست‌های اختیاری RLS برای میزبانی دیتابیس روی Supabase.
- `DESIGN.md`: توکن‌ها، اجزا، فونت‌ها و راهنمای طراحی قابل ویرایش.

Firebase و Supabase Auth در نسخهٔ اجرایی استفاده نشده‌اند. برای استفاده از **Supabase PostgreSQL** می‌توان DATABASE_URL را تغییر داد؛ UI، API و احراز هویت مالک همچنان روی Next.js می‌مانند.

### امکانات عمومی
جستجوی هیرو، فیلتر Role/Lane/Difficulty، علاقه‌مندی محلی، هیروی هفته، مهارت‌ها، لور، نمودار رادار، بیلدهای تأییدشده، کانتر پیکر، جمع آمار بیلد شش‌آیتمی و مقایسه با پیشنهاد ادمین، ذخیرهٔ محلی بیلد، پیشنهاد بیلد، رأی‌دهی، نظراتِ نیازمند تأیید، گزارش خطا، مقالهٔ Markdown و ویدیو، تایمرهای مستقل و ابزار آموزشی ایمبلیم.

### امکانات مالک
ورود ایمیل/رمز + TOTP، مدیریت هیرو/آیتم/بیلد/آموزش، ویرایش Stats/Skills/Counter، انتخاب هیروی هفته، آپلود تصویر و ویدیو، تأیید یا رد پیشنهادها و نظرات، حل گزارش‌ها، آمار واقعی بازدیدها و دستیار نگارش OpenAI با تأیید دستی.

**اعداد نمونه:** اطلاعات اولیه شامل ۱۶ هیرو، ۱۴ آیتم، ۱۶ بیلد و ۵ مقاله است. Tier، نرخ برد، هزینه‌ها و مقادیر مهارت نمونهٔ آموزشی هستند و دادهٔ زنده یا تضمین‌شدهٔ پچ جاری نیستند. پیش از انتشار واقعی، مالک باید داده‌ها را بازبینی کند. ابزار بیلد جمعِ آمار پایه و آمار ثابت آیتم‌هاست؛ فرمول مبارزه، penetration، unique passive، درصدها و رشد level را شبیه‌سازی نمی‌کند. ایمبلیم نیز مدل خطی نمونه است.

## ۲. اجرای وب

نیازمندی‌ها: Node.js 22، npm، PostgreSQL 14+.

1. وابستگی‌ها را با `npm install` نصب کنید.
2. متغیرهای `.env.example` را در محیط خصوصی خود تنظیم کنید. فایل `.env` موجود را کورکورانه جایگزین نکنید.
3. `DATABASE_URL` را به دیتابیس خصوصی اختصاصی تنظیم کنید. تنظیم Drizzle و برنامه هر دو همین متغیر را می‌خوانند.
4. برای یک محیط تازه: `npx drizzle-kit push`.
5. توسعه: `npm run dev`.
6. تولید: `npx next typegen`، سپس `npm exec tsc -- --noEmit` و `npm run build`.
7. روی میزبان خود، build را با سرویس Node یا کانتینر اجرا کنید. پروژهٔ پیش‌نمایش از runtime مدیریت‌شدهٔ پلتفرم استفاده می‌کند؛ سرور دوم روی همان پورت راه نیندازید.

داده‌های اولیه در نخستین درخواست عمومی و داخل transaction با advisory lock ثبت می‌شوند. شروع مجدد برنامه، محتوای موجود را بازنویسی نمی‌کند. برای نسخه‌های بعدی تولید از migration نسخه‌بندی‌شده با `npx drizzle-kit generate` و `npx drizzle-kit migrate` استفاده کنید؛ `push` برای شروع و توسعه مناسب است.

مسیر `GET /api/health` سلامت اتصال PostgreSQL را بررسی می‌کند.

## ۳. دسترسی مالک و 2FA

**هیچ رمز پیش‌فرض یا درِ پشتی وجود ندارد.** فعال‌سازی ورود به هر چهار متغیر زیر نیاز دارد:

- `ADMIN_EMAIL`
- `ADMIN_PASSWORD_HASH`
- `ADMIN_TOTP_SECRET`
- `SESSION_SECRET`

روی دستگاه امن خود اجرا کنید:

`node scripts/setup-admin.mjs you@example.com`

اسکریپت یک رمز تصادفی قوی، salt و hash مبتنی بر scrypt، secret تصادفی TOTP و SESSION_SECRET می‌سازد. برای استفاده از رمز انتخابی می‌توانید آن را از طریق متغیر محیطی `ADMIN_SETUP_PASSWORD` به اسکریپت بدهید. رمز باید حداقل ۱۲ کاراکتر باشد. رمز را در command history، فایل عمومی یا مخزن کد قرار ندهید.

1. مقادیر خروجی را در secret manager میزبان قرار دهید.
2. TOTP secret را در برنامه‌ای مانند Aegis، 1Password یا Google Authenticator ثبت کنید (۶ رقم، SHA-1، بازهٔ ۳۰ ثانیه).
3. URI تولیدشده نیز یک secret است؛ آن را برای ساخت QR به وب‌سایت‌های عمومی نفرستید.
4. سرور را بازراه‌اندازی کنید.
5. در `/admin` ایمیل، رمز و کد جاری را وارد کنید.

امنیت ورود:

- مقایسهٔ ثابت‌زمان و scrypt salted؛ رمز خام در دیتابیس ذخیره نمی‌شود.
- TOTP با تلورانس ±۳۰ ثانیه و جلوگیری از استفادهٔ دوباره از یک counter.
- ۱۰ تلاش در ۱۵ دقیقه برای حساب مالک، با شمارندهٔ مشترک PostgreSQL.
- نشست ۸ساعتهٔ امضاشده در کوکی HttpOnly / SameSite=Strict / Secure در production.
- برای ابطال همهٔ نشست‌ها SESSION_SECRET را تغییر دهید.
- بازیابی دسترسی فقط از طریق دسترسی مدیریتی به secret manager و تعویض مقادیر است؛ reset عمومی وجود ندارد.

`SESSION_SECRET` باید در تمام instanceها ثابت و مشترک باشد. اگر تنظیم نشود، نشست ناشناس پیش‌نمایش از کلید موقتی process استفاده می‌کند و با restart اعتبارش را از دست می‌دهد؛ ورود ادمین در این وضعیت غیرفعال است.

## ۴. مدل امنیت و دسترسی دیتابیس

مرورگر هیچ connection string یا credential دیتابیس دریافت نمی‌کند. همهٔ نوشتن‌ها از سرور و با Drizzle انجام می‌شوند.

- محتوای عمومی: `GET /api/catalog` بدون login، فقط هیرو/آیتم/مقاله و بیلد تأییدشده.
- mutation عمومی: ابتدا `GET /api/session`، سپس کوکی ناشناس HttpOnly + `x-csrf-token` + Origin معتبر. این مسیر فقط رأی، بازدید و صف تعاملات را می‌نویسد؛ نمی‌تواند هیرو یا آیتم را تغییر دهد.
- پیشنهاد بیلد: شش آیتم متفاوت، حداکثر یک Boots، اعتبارسنجی شناسه‌ها، وضعیت pending.
- نظر و گزارش: محدودیت طول و ۴۰ تعامل در ساعت برای نشست مرورگر.
- رأی: یک رأی قابل‌تغییر برای هر هیرو و نشست مرورگر، با unique index.
- بازدید: برای همان مرورگر و هیرو در هر ۳۰ دقیقه deduplicate می‌شود. آمار «فعال» تعداد مرورگرهای بازدیدکنندهٔ هیرو در ۲۴ ساعت اخیر است، نه حساب‌های احرازشده یا DAU سرویس رسمی بازی.
- endpointهای مالک: همان CSRF/Origin، به‌علاوهٔ نشست امضاشدهٔ نقش ادمین.
- AI: فقط سرور/ادمین؛ بدون ابزار نوشتن و بدون اتصال مدل به دیتابیس.
- Markdown بدون raw HTML رندر می‌شود.
- public cache و service worker، `/admin` و APIهای حساس را ذخیره نمی‌کنند.

توکن برای **mutationها** لازم است؛ خواندن کاتالوگ به‌عمد عمومی است تا اپ بدون ثبت‌نام و آفلاین کار کند. حذف کوکی مرورگر، شناسهٔ ناشناس جدیدی ایجاد می‌کند؛ این سیستم جایگزین حساب کاربری احرازشده، CAPTCHA یا محافظت کامل ضدتقلب نیست. برای مقیاس عمومی، rate limit لبه بر اساس IP قابل اعتماد، WAF، سیاست حریم خصوصی و حفاظت ضدسوءاستفاده اضافه کنید. آمار و محتوای گزارش‌ها هرگز به بازدیدکنندهٔ غیرادمین داده نمی‌شوند.

## ۵. Supabase به‌عنوان میزبان PostgreSQL

1. پروژهٔ Supabase بسازید.
2. connection string سمت سرور (ترجیحاً session pooler یا اتصال مستقیم با TLS) را در DATABASE_URL قرار دهید.
3. اسکیمای Drizzle را با migration یا `database/schema.sql` اعمال کنید؛ هر دو را دوباره روی دیتابیس موجود اجرا نکنید.
4. `database/supabase-access.sql` را اجرا کنید.
5. هیچ `service_role` key یا رمز PostgreSQL را در Flutter یا متغیر `NEXT_PUBLIC_*` قرار ندهید.

فایل سیاست‌ها نوشتن مستقیم نقش‌های anon/authenticated را لغو و RLS را فعال می‌کند. خواندن فقط برای جداول عمومی و بیلد تأییدشده باز است؛ داده‌های خصوصی فقط از API سرور خوانده می‌شوند. credential سمت سرور باید مجوز لازم برای کار خود را داشته باشد و هرگز کلاینتی نباشد.

## ۶. OpenAI

- کلید را فقط در `OPENAI_API_KEY` قرار دهید.
- مدل پیش‌فرض `gpt-4.1-mini` است؛ با `OPENAI_MODEL` قابل‌تغییر است و باید در حساب شما قابل استفاده باشد.
- endpoint سرور: `POST /api/admin/ai`.
- endpoint ارائه‌دهنده: `POST https://api.openai.com/v1/responses`.
- متن ۱۰ تا ۱۲۰۰۰ کاراکتر؛ حداکثر ۲۴۰۰ توکن خروجی؛ timeout برابر ۶۰ ثانیه؛ `store:false`.
- مدل زبان ورودی، از جمله فارسی، را حفظ می‌کند و مأمور به اختراع‌نکردن اعداد است. تضمینی برای صحت خروجی AI نیست؛ بازبینی انسان لازم است.
- «Use in editor» فقط فیلد ویرایش محلی را پر می‌کند. تنها «Save & publish» دادهٔ عمومی را عوض می‌کند.
- نبود کلید با پیام واضح نشان داده می‌شود؛ پاسخ ساختگی به‌جای AI تولید نمی‌شود.

## ۷. فایل‌ها و ویدیو

فایل‌های آپلودشده در جدول `media` به‌صورت base64 ذخیره می‌شوند تا در محیط‌های بدون دیسک پایدار نیز باقی بمانند. تصویر: PNG/JPG/WebP تا ۵MB؛ ویدیو: MP4/WebM تا ۱۵MB. فایل SVG یا اجرایی پذیرفته نمی‌شود. route رسانه از Range requests برای پخش ویدیو پشتیبانی می‌کند. URL ویدیوی YouTube نیز قابل استفاده است.

برای مقیاس واقعی، ذخیره‌سازی ویدیو در object storage خصوصی/عمومی مناسب (مانند Supabase Storage) و CDN بهتر از base64 در PostgreSQL است. فایل حذف‌شده از مقاله به‌صورت خودکار از جدول media پاک نمی‌شود؛ سیاست پاکسازی فایل‌های بدون مرجع را متناسب با محصول اضافه کنید.

## ۸. آفلاین، کارایی و زبان

- تصاویر WebP محلی، فونت‌های self-hosted، lazy loading کارت‌های پایین و CSS واکنش‌گرا.
- PWA از HTTPS نصب می‌شود. در iOS از Share → Add to Home Screen استفاده کنید.
- پس از پیام «Library cached for offline use»، app shell، فایل‌های اجرایی و hero library برای مراجعهٔ بعدی کش شده‌اند.
- حداقل یک بازدید آنلاین لازم است. بدون اینترنت ثبت رأی/نظر/بیلد یا عملیات ادمین ممکن نیست؛ اپ ادعای ذخیرهٔ سروری نمی‌کند.
- cache بازدید قبلی می‌تواند قدیمی باشد؛ با اتصال دوباره، کاتالوگ تازه دریافت می‌شود.
- دکمهٔ EN/FA ناوبری و صفحهٔ اصلی را تغییر جهت می‌دهد. ابزارها و داده‌های نمونه عمدتاً انگلیسی‌اند؛ هر مقاله در زبان نوشته‌شده نمایش داده می‌شود. ترجمهٔ کامل همهٔ محتوا تحویل نشده است.
- کمتر از ۳ ثانیه هدف است، نه تضمین روی هر شبکه. با دادهٔ واقعی، دیتابیس نزدیک سرور، CDN و Lighthouse روی دستگاه مقصد اندازه‌گیری کنید.

## ۹. Flutter Android/iOS

نیازمندی: Flutter stable 3.27+، Dart 3.6+، Android SDK 24+، Xcode و iOS 13+ برای خروجی iOS.

1. یک پروژهٔ پلتفرمی بسازید: `flutter create --platforms=android,ios --org com.yourcompany nexus_mobile`.
2. `mobile/pubspec.yaml` را روی pubspec پروژه کپی کنید.
3. `mobile/lib/main.dart` را روی `lib/main.dart` کپی کنید.
4. تست نمونهٔ تولیدشدهٔ Flutter را با `mobile/test/widget_test.dart` جایگزین کنید.
5. در AndroidManifest اصلی، مجوز `android.permission.INTERNET` را اضافه کنید.
6. در تنظیمات Android مقدار minSdk را 24 یا بالاتر قرار دهید. deployment target iOS را 13.0 یا بالاتر قرار دهید.
7. `flutter pub get`، سپس `flutter analyze` و `flutter test`.
8. اجرا: `flutter run --dart-define=NEXUS_URL=https://your-domain.example`.
9. Android: `flutter build appbundle --dart-define=NEXUS_URL=https://your-domain.example`.
10. iOS: `flutter build ipa --dart-define=NEXUS_URL=https://your-domain.example`، با signing account معتبر Apple.

این پوسته فقط URL HTTPS هم‌مبدأ را به‌عنوان صفحهٔ اصلی می‌پذیرد و مسیر `/admin` را در اپ عمومی باز نمی‌کند. کلید API یا دیتابیس در Flutter وجود ندارد. کتابخانهٔ بومی با فایل‌های محلی و تصاویر دانلودشده در application support directory کار می‌کند. Flutter SDK، امضای iOS/Android و شبیه‌ساز در محیط ساخت این وب‌اپ وجود ندارند؛ خروجی APK/IPA یا تأیید build بومی در این تحویل ادعا نمی‌شود. پیش از انتشار، رفتار WebView، ویدیو، دکمهٔ Back و شبکه را روی دستگاه‌های واقعی تست کنید. پوستهٔ صرفاً وب ممکن است برای تأیید App Store به قابلیت‌های بومی بیشتری نیاز داشته باشد.

## ۱۰. تست و نگهداری

وب: `npx next typegen`، `npm exec tsc -- --noEmit --pretty false`، `npm run build`.

پس از اجرای production server، تست دود: `BASE_URL=http://localhost:3000 node scripts/smoke-test.mjs`. این تست روی دیتابیس یک رأی، نظر و پیشنهاد بیلد نمونه ثبت می‌کند؛ در production با داده‌های واقعی اجرا نکنید. اسکرین‌شات‌های تست در `artifacts/` قرار می‌گیرند.

آزمون مستقل مالک: `node scripts/admin-integration-test.mjs`. این اسکریپت یک سرور موقت فقط روی loopback با اعتبارنامهٔ تصادفیِ حافظه‌ای اجرا می‌کند، ورود/2FA/CRUD/آپلود/تأیید نظر را بررسی می‌کند و سرور را می‌بندد. credentialها ذخیره یا چاپ نمی‌شوند. فقط روی دیتابیس آزمایشی اجرا شود؛ فایل آپلود نمونه و سوابق ورود ممکن است برای پاکسازی باقی بمانند. این تست به OpenAI واقعی درخواست نمی‌فرستد و نبود کلید را بررسی می‌کند.

- PostgreSQL را عمومی نکنید و روزانه backup بگیرید.
- HTTPS در تولید لازم است. Secure cookie با HTTP غیرمحلی کار نمی‌کند.
- ساعت سرور و دستگاه authenticator را با NTP همگام نگه دارید.
- قبل از ارتقای وابستگی‌ها `npm audit` و changelogها را بررسی کنید. هیچ اجرای `audit fix --force` بدون بازبینی توصیه نمی‌شود.
- برای private IPهای proxy از headerهای forwarded فقط پشت reverse proxy کنترل‌شده استفاده کنید.
- CSP فعلی برای سازگاری hydration Next از inline script استفاده می‌کند؛ برای سخت‌گیری بیشتر nonce-based CSP را در زیرساخت نهایی پیاده کنید.

## ۱۱. حقوق تصاویر و انتشار

Nexus مستقل از MOONTON است و وابسته یا تأییدشدهٔ Mobile Legends نیست. تصاویر هیروها از منابع عمومی مرتبط با بازی برای نمونهٔ آموزشی گرفته شده‌اند؛ قبل از توزیع تجاری، مجوز و شرایط استفادهٔ صاحب اثر را بررسی کنید. بنر اصلی تصویر تولیدشدهٔ اختصاصی است و تصویر رسمی یک هیرو معرفی نشده است. فونت‌ها طبق SIL Open Font License هستند؛ فایل‌های مجوز در `public/fonts` موجودند.
